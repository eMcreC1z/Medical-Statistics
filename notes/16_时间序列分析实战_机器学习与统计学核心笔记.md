# 《时间序列分析实战：基于机器学习和统计学》核心笔记

## 0. 阅读定位与证据边界

本笔记依据 Aileen Nielsen 的 *Practical Time Series Analysis* 中文版整理。全书共 17 章，结构不是从某一种预测算法出发，而是覆盖时间序列项目的完整生命周期：

1. 时间序列分析的历史与应用；
2. 时间序列的发现、整理、清洗、模拟与存储；
3. ARIMA、状态空间、机器学习和深度学习建模；
4. 特征工程、预测误差、模型验证与性能权衡；
5. 医疗、金融、政务案例，以及规模化预测和异常检测工具。

全书可以压缩为一条数据科学主线：

\[
\text{业务或科学问题}
\rightarrow
\text{时间语义与数据可用性}
\rightarrow
\text{数据整理和防前瞻}
\rightarrow
\text{统计/机器学习候选模型}
\rightarrow
\text{保持时间顺序的验证}
\rightarrow
\text{部署、监测和更新}.
\]

> **来源边界**：下文“书中主线”保留原书的章节组织、术语和案例方向；关于医学 estimand、校准、外部验证、决策效用、模型治理等内容标为“科研/工程实践扩展”，不应视为原书逐字结论。书中示例反映其成书时期的 Python、R 和深度学习生态，具体接口必须在当前环境重新核验。

## 1. 时间序列项目首先是时间语义工程

普通表格中，行顺序经常可以交换；时间序列中，顺序本身携带趋势、季节、滞后、记忆、冲击传播和信息可用性的结构。开始建模前至少应定义：

| 问题 | 必须记录的内容 |
|---|---|
| 时间戳代表什么 | 事件发生、测量、入库、审核、发布或修订时间 |
| 时间尺度 | 秒、小时、日、周、月；是否与生物或业务机制一致 |
| 时间基准 | 时区、夏令时、自然日、工作日、流行病学周 |
| 采样机制 | 规则采样、事件触发、传感器触发、临床就诊触发 |
| 可用时间 | 某变量在预测时点是否已真实可见 |
| 修订机制 | 初报值、补报值和最终值是否区分并保留历史版本 |

一个字段名为 `date` 并不能证明数据具备正确时间语义。临床事件发生时间、医嘱录入时间、标本采集时间、检验报告时间和模型调用时间可能完全不同。

### 1.1 “发现的时间序列”尤其危险

原书强调，很多时间序列并非为分析目的主动设计，而是从业务数据库、日志或多个表中事后组装。这类数据常见问题包括：

- 重复时间戳或同一时间多个记录；
- 不同实体的记录被错误串联；
- 时间戳由文件写入或数据迁移生成，而非事件发生时间；
- 观测频率由就诊或设备行为决定；
- 早期年份与后期年份的检测制度不同；
- 修订后的“最终数据”被误用于历史实时预测验证。

因此，时间序列数据集应同时保存实体键、事件时间、可用时间、数据版本和来源系统。

## 2. 清洗时间序列时，缺失、零和未发生不能混为一谈

### 2.1 缺失值的五种含义

1. 理论时点存在，但测量失败；
2. 事件没有发生，因此没有记录；
3. 数据尚未报告或尚未完成审核；
4. 设备停机或患者脱离监测；
5. 数据因抽样、过滤或权限规则未进入分析表。

其中只有第二种情形有时可以编码为 0。将“未知”编码为 0 会同时扭曲水平、趋势、方差、自相关和模型目标。

### 2.2 插值不是中性操作

前向填充、后向填充、线性插值、样条插值和移动平均都会引入结构。采用任何填补方法前应说明：

- 该过程在缺失区间内是否足够平滑；
- 插值是否使用了未来信息；
- 连续缺失区间有多长；
- 缺失本身是否携带临床信息；
- 填补值是否被误当作真实观测进入损失函数。

在医疗监测中，缺失模式常与病情、护理强度、设备脱落和出院死亡有关。缺失指示、距上次观测时间和观测频率本身可能是预测特征，但其使用必须尊重预测时点的信息集。

### 2.3 上采样和下采样

- **上采样**创建更密集的时间网格，通常伴随缺失或插值；它不会创造新的独立信息。
- **下采样**通过总和、均值、中位数、末值、最大值等聚合降低频率；不同聚合函数对应不同科学问题。
- 聚合窗口的起点、闭区间规则和标签位置必须固定，否则同一数据可得到不同序列。
- 高频信号下采样前应考虑混叠；低频汇总会掩盖短时峰值和持续时间。

医学例子中，“日均血糖”“每日最高血糖”“高于阈值的时间比例”和“夜间低血糖次数”不是同一估计对象。

## 3. 探索性分析：同时查看水平、变化和时间尺度

### 3.1 基本图形仍然必要

原书使用折线图、直方图和散点图作为起点，但强调对时间序列不能只看原始水平。至少应并列检查：

- 原始序列；
- 一阶和季节差分；
- 不同窗口的滚动均值、滚动方差和滚动分位数；
- 按小时、星期、月份、季节或中心分层的分布；
- 事件前后的局部窗口；
- 同期资料的可用性与缺失模式。

两条具有共同趋势的序列可能表现出极高相关，却没有稳定的动态关系。去趋势、差分或预白化后再检查关系，是识别伪相关的重要步骤。

### 3.2 平稳性是模型性质，不是数据标签

平稳性需要明确是严格平稳、弱平稳，还是某种局部稳定。现实数据往往存在：

- 均值漂移；
- 方差变化；
- 周期和季节幅度变化；
- 结构突变；
- 采样和报告制度变化；
- 不同亚群构成随时间变化。

“通过一次单位根检验”不能证明序列适合某一模型。图形、领域机制、结构变化和残差诊断需要共同判断。

## 4. 模拟时间序列是理解模型和验证分析链的核心工具

原书将模拟分为规则或代码驱动模拟、物理模拟、统计模拟和深度学习生成。模拟至少有四种用途：

1. 验证代码是否能恢复已知机制；
2. 比较不同模型在趋势、季节、异常、缺失和漂移下的行为；
3. 评估预测区间覆盖率及多步误差累积；
4. 生成受控训练数据或隐私保护的合成数据。

### 4.1 统计模拟

当底层随机过程可被明确描述时，可生成 AR、MA、ARIMA、状态空间或其他过程，研究参数估计和预测误差。这一方式最适合回答“在假定成立时方法是否工作”。

### 4.2 深度生成模型

深度生成模型能够学习复杂非线性结构，也可用于合成医疗序列；但“看起来逼真”不等于：

- 保留了临床关联；
- 保护了个体隐私；
- 不会复现训练样本；
- 对下游任务无偏；
- 能替代真实外部验证。

**科研实践扩展**：合成数据应分别评价统计保真度、任务保真度、隐私泄露风险和亚群公平性。

## 5. 存储设计决定能否开展可靠回顾性验证

原书讨论 SQL、NoSQL、时间序列数据库、NumPy、Pandas、R 标准格式和 Xarray。方法选择应服从查询与重建需求，而不是追逐某一种数据库。

时间序列仓库应尽量保留：

- 原始粒度数据；
- 事件时间与系统时间；
- 数据修订版本；
- 实体、设备、中心和来源键；
- 单位、采样频率和质量标志；
- 由原始数据派生特征的版本与代码哈希。

只保留最终聚合特征而删除原始信号，会使后续无法审计窗口、前瞻、异常和单位错误。

## 6. 统计时间序列模型：显式建模动态结构

### 6.1 AR、MA、ARIMA 与 VAR

- AR 模型以过去观测解释当前值；
- MA 模型以过去创新解释当前值；
- ARIMA 通过差分处理非平稳水平，再对差分序列建模；
- VAR 联合描述多个序列的滞后关系。

这些模型的优势是参数含义和预测递推较清晰，且能显式检查残差。局限是对结构突变、复杂非线性、高维输入和长程依赖的表达可能不足。

### 6.2 状态空间模型

状态空间框架区分潜在状态和观测：

\[
\alpha_t=T_t\alpha_{t-1}+R_t\eta_t,
\qquad
Y_t=Z_t\alpha_t+\varepsilon_t.
\]

它可以把趋势、季节、回归效应和随机变化组合在一个系统中。

必须区分：

- **滤波**：使用截至时点 \(t\) 的信息估计当前状态；
- **平滑**：使用完整序列估计过去状态；
- **预测**：使用当前信息推断未来状态或观测。

平滑结果使用未来信息，不能直接作为实时预测特征。

### 6.3 卡尔曼滤波、HMM 与贝叶斯结构时间序列

- 卡尔曼滤波适合线性高斯状态空间系统；
- HMM 通过离散潜在状态描述阶段转换；
- 贝叶斯结构时间序列可组合趋势、季节、回归、变量选择和后验预测。

状态或成分的后验图形有助于解释，但可识别性仍取决于模型约束和数据长度。多个成分可能以不同组合解释相似的观测轨迹。

## 7. 特征工程：机器学习获得“时间意识”的关键

许多树模型、线性分类器和常规机器学习算法本身不知道时间。时间结构必须通过特征和验证设计引入。

### 7.1 常见特征族

| 特征族 | 示例 | 主要风险 |
|---|---|---|
| 滞后 | \(Y_{t-1},Y_{t-7}\) | 预测时不可获得、错位 |
| 滚动统计 | 过去 24 小时均值、最大值、波动 | 窗口包含当前结局或未来值 |
| 差分与增长率 | 日变化、同比变化 | 小分母和噪声放大 |
| 日历 | 小时、星期、节假日、季节 | 制度和地区差异 |
| 频域与形状 | 主周期、谱能量、峰数、斜率 | 序列长度不一致 |
| 事件史 | 距上次住院、累计暴露次数 | 时间零点不清 |
| 缺失模式 | 距上次测量、缺失比例 | 观测过程与病情混杂 |
| 领域特征 | 葡萄糖变异、心率变异、用药窗口 | 定义不一致或不可复现 |

### 7.2 特征必须在训练窗口内生成

所有涉及数据分布的步骤都应在训练窗口内估计：

- 标准化参数；
- 缺失填补规则；
- 特征筛选；
- PCA；
- 阈值和超参数；
- 异常值截断界值。

先用全数据生成滚动、标准化或选择特征，再进行验证，会发生前瞻或信息泄漏。

### 7.3 长度和采样频率影响特征

最大值、最小值、峰数和极端持续时间会随序列长度增加而改变。比较不同患者或设备的序列特征时，应控制观察窗、最少观测数、采样频率和缺失比例。

## 8. 时间序列机器学习：分类、聚类与时间感知距离

### 8.1 分类

时间序列分类可采用两条路径：

1. 把一段序列转换为固定长度特征，再使用树、线性模型或集成学习；
2. 使用能直接处理序列的 CNN、RNN 或其他架构。

第一条路径更易解释和审计，第二条路径保留更多原始时序结构，但需要更多数据和严格验证。

### 8.2 聚类

时间序列聚类可基于：

- 原始或标准化轨迹；
- 生成的统计特征；
- 相关或频域特征；
- 时间感知距离，如允许局部对齐的距离。

聚类算法一定会给出分组。必须进一步评价重抽样稳定性、不同距离和标准化下的一致性、临床可解释性及外部可复现性。

---

## 9. 深度学习：更灵活，但不是自动免除假定

原书介绍前馈网络、注意力、卷积网络、循环网络、自编码器和组合架构。深度学习的优势是能处理高维、非结构化和复杂非线性序列；但它不是“无需预处理和验证”的银弹。

### 9.1 主要架构

- 前馈网络：需要固定长度特征或窗口；
- CNN：提取局部形状和多尺度模式；
- RNN/LSTM/GRU：递归表示历史信息；
- 自编码器：学习低维表示或异常结构；
- 注意力：对不同时间位置赋予数据驱动权重；
- 组合模型：将卷积、循环、注意力和静态协变量结合。

### 9.2 常见失败方式

- 数据量不足，模型参数远多于有效独立信息；
- 随机拆分导致同一患者或相邻时间片进入训练和测试；
- 趋势和尺度未经处理；
- 超参数搜索使用了测试集；
- 只报告点预测，不量化不确定性；
- 与简单季节基线相比没有实质提升；
- 性能来自标签泄漏、监测强度或中心特异性流程。

**科研实践扩展**：深度模型至少应与最近值、季节最近值、线性/GLM、指数平滑或低阶 ARIMA 等基线比较，并报告增量价值。

## 10. 多步预测不是把一步预测重复多次这么简单

原书讨论三种基本策略：

1. **直接法**：为每个预测步长单独拟合目标；
2. **递归法**：将前一步预测作为下一步输入；
3. **多任务法**：同时预测多个相关步长。

递归法会累积误差；直接法忽略不同步长之间的约束；多任务法需决定各步长损失权重。评价时应按 \(h=1,2,\ldots,H\) 分别报告误差和区间覆盖，而不是用一个总分掩盖远期性能下降。

## 11. 模型验证：时间边界高于随机交叉验证

原书反复强调，标准随机交叉验证通常不适用于时间序列。合格验证应模拟模型实际使用时的信息边界。

### 11.1 常见划分

- 末端固定测试期；
- 扩展窗口滚动起点；
- 固定宽度滚动窗口；
- 按患者、医院、地区或设备分组后，再保持时间顺序；
- 多中心内部—外部交叉验证；
- 前瞻性静默验证。

### 11.2 评价指标

| 任务 | 推荐指标 |
|---|---|
| 连续点预测 | MAE、RMSE、尺度化误差、分位数误差 |
| 概率预测 | 对数评分、Brier 分数、CRPS、覆盖率和区间宽度 |
| 分类 | 灵敏度、特异度、AUROC、AUPRC、校准、决策效用 |
| 事件预警 | 固定提前量下召回、每患者日误报数、报警负担 |
| 异常检测 | 事件级召回、检测延迟、误报间隔 |

MAPE 在真实值接近 0 时不稳定。不同任务的误差成本不同，应根据决策场景设置损失，而不是只追求单一平均误差。

### 11.3 不确定性必须被验证

预测区间不仅要画出来，还要评价：

- 名义覆盖率与经验覆盖率；
- 不同预测步长的覆盖；
- 不同中心和亚群的覆盖；
- 区间宽度与决策价值；
- 结构变化后是否失效。

## 12. 医疗保健案例的核心启示

原书通过流感预测和血糖预测展示医疗时间序列的实际困难。

### 12.1 流感预测

关键挑战包括：

- 报告延迟与后续修订；
- 地区异质性；
- 季节模式并非每年固定；
- 疫苗、行为、气候和检测政策共同变化；
- 疫情峰值和转折点比平均误差更重要。

实时评价应使用每个历史时点当时可获得的数据版本，而不是最终修订后的完整序列。

### 12.2 血糖预测

连续血糖、饮食、胰岛素、运动和睡眠具有不同时间尺度。特征设计应明确：

- 预测起点；
- 预测范围；
- 可用的既往窗口；
- 用药和进食记录的时间误差；
- 患者内与患者间差异；
- 低血糖与高血糖错误的非对称代价。

随机切分相邻窗口会严重高估泛化能力。需要按患者和时间双重隔离，并区分个体化模型与跨患者模型。

## 13. 性能与部署：最复杂模型不一定是最佳系统

原书讨论存储格式、滑动预处理、延迟、预计算和高性能工具。生产系统的目标函数通常是：

\[
\text{统计性能}
+\text{延迟}
+\text{稳定性}
+\text{可维护性}
+\text{可解释性}
+\text{成本}.
\]

只比较离线精度会遗漏：

- 特征生成是否能在截止时间内完成；
- 输入延迟或缺失时是否有降级策略；
- 模型和数据版本能否重建；
- 漂移如何被发现；
- 预测失败由谁处置；
- 复杂模型是否带来足够增益。

## 14. 医学时间序列项目最低核查表

### 数据与时间

- [ ] 时间戳语义、时区、频率和窗口边界已定义；
- [ ] 理论时点、实际时点、重复和缺失已核查；
- [ ] 事件时间、可用时间和修订时间已分开；
- [ ] 零值与未知值未混淆；
- [ ] 分母、暴露时间和人群构成变化已处理。

### 建模

- [ ] 至少有一个透明统计基线；
- [ ] 所有特征在预测时点可获得；
- [ ] 所有数据驱动步骤均在训练窗内完成；
- [ ] 候选模型复杂度与有效样本信息相称；
- [ ] 残差、校准和不确定性已检查。

### 验证与部署

- [ ] 验证保持患者、中心和时间边界；
- [ ] 按预测步长和关键亚群报告性能；
- [ ] 与简单基线比较增量价值；
- [ ] 评价预测区间覆盖和临床决策效用；
- [ ] 建立漂移、失败和回滚机制。

---

## 15. 精通层面的结论

1. 时间序列问题中最危险的错误通常不是模型阶数，而是时间戳、可用性和前瞻定义错误。
2. 数据清洗、采样、插值和特征工程都会改变随机结构，因此属于模型的一部分。
3. 统计模型、机器学习和深度学习是互补工具；选择应由任务、信息量、解释要求和部署约束决定。
4. 深度学习的灵活性不能替代患者级隔离、时间顺序验证、概率预测和基线比较。
5. 医学时间序列模型的最终质量取决于“实时可用数据—正确验证—临床决策—持续监测”的闭环，而不是离线排行榜。
